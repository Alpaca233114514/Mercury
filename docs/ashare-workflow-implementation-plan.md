# A股自主模拟流程完善计划

用户授权：先制定计划，由子代理实现，最后主代理亲自review。范围为A股优先、CNY独立账户、真实行情只读、本地假钱；FDM全球对照保留。未授权券商/真钱、提交、推送或删除旧数据。

实施状态（2026-09-27）：上述本地开发与验收已完成。三个实现子代理交付后，第四个独立审计子代理复核，主代理亲读代码、修复反例、复算账本并运行最终145项测试和完整CLI流程。证据见[验收报告](repository-acceptance.md)与[独立审计](workflow-independent-audit.md)。真实模型API、交易日新行情前向成交、日内Sharpe网格、OS隔离与长期严格基准仍是明确未验证/未实现范围，不算本轮模拟验证成绩。

## 验收目标

形成可运行的 `Observation → Research/Strategy JSON → TradeIntent → deterministic risk → local paper fills → review → next cycle`。外部模型只接收已冻结资料并返回结构化数据，不执行其生成的Python、shell、SQL或工具指令。

1. **冻结观察**：按cutoff筛选行情、公告/新闻、财报和证券状态；稳定内容ID、来源哈希、版本、缺失说明。模型输入不包含完整未来历史capture或内部文件路径。账户snapshot与市场Observation分开；相同市场输入可供不同账户共享。
2. **严格策略与意图**：研究依据、策略版本、as_of、Observation引用、股票池、受限信号/选择/再平衡、持有期与失效条件均有严格schema；未知字段/类型、非有限数字、空依据、未引用的资料、未来时间等拒绝。不eval/exec模型输出。
3. **硬风控**：显式且持久化的CNY单笔金额、单标的仓位、日换手、日亏损限额，考虑手续费及未成交预留；禁止杠杆/做空，缺估值或资料时拒绝。下单和成交均复核，重试/并发不能越限；拒绝原因留档，不静默裁剪。已启用策略的账户不能通过旧buy/match命令绕过检查。
4. **运行与权限边界**：受控运行器持有账户写权限和行情源；模型通过固定数据协议获取冻结观察、返回JSON，不提供任意命令执行接口。模型API凭证仅从环境取得，不进入观察、日志或证据。将应用协议边界与OS强隔离分别说明，不声称能限制同一宿主管理员。
5. **自主循环**：可配置模型适配器/可复现离线agent，研究、策略、风控、执行、复盘分阶段留档，支持幂等、错误恢复和有限轮次；不安装后台定时任务。可运行一个完整合成cycle及多轮episode，并对真实已保存行情验证适用/拒绝路径。
6. **回测与统一评测**：受限策略解释器、时序回放、同观察/初始CNY资金/规则与费用、多模型episode和对齐基准。指标补换手、完整交易分组；Sharpe仅在明确频率与完整连续序列时计算，否则返回原因。记录样本数、时间窗、缺失、费用、滑点及局限。
7. **撮合模型**：显式可配置价差、执行延迟和部分成交，不覆盖旧实验配置；无真实盘口/成交量证据时仅称参数化模拟。默认配置保持已有行为，部分成交释放/保留资金、持仓、T+1批次及费用正确，撤单只撤剩余量。
8. **文档与审计**：三语README命令一致、A股主路径明确；实现者之外的子代理独立审计，然后主代理亲自review、复算和端到端验证。合成测试、真实行情接入与真实前向收益分别报告。

## 分工与接口约定

- **数据/策略子代理**：`observation.py`、`strategy.py`、相应测试。提供纯JSON、标准库接口；Observation公开输入必须裁掉未来原文，保留可追溯引用。负责严格策略/意图验证和受限DSL解释，向编排层输出订单意图。
- **风控/撮合子代理**：`risk.py`、`engine.py`、`cn.py`、`audit.py`/`cn_audit.py`及对应回归。先实现风控与公共API，再加入可配置价差/延迟/部分成交；保留旧账本读取，不强制迁移用户实验库。
- **编排/评测子代理**：`workflow.py`、模型适配器、回测/比较/指标、CLI接入和对应测试。复用其他两组接口；不得另建绕开PaperTrader和风控的成交计算器。
- **主代理**：协调接口、检查现有修改、集成评审和最终端到端验收；不以子代理“通过”替代亲自阅读与复算。
- **独立审计子代理**：由未参与以上实现的新审计者承担；只读检查和临时反例，不改实现或历史账本。

公共数据基本约束：时间统一显式时区；金额/价格使用Decimal可解析的字符串；标的必须带交易所；Observation、策略、意图和cycle都有版本与稳定ID。策略数据不能携带账户路径、数据库命令或执行价格。不同模块的具体函数签名在实施前协商并记录，避免多代理同时改同一文件。

## 实施顺序

1. 核对现有78项测试与真实证据，敲定跨模块签名。
2. 并行实现冻结/策略、风控核心、编排骨架；各自做有意义的边界测试。
3. 接通完整cycle和回测，补齐撮合模型及指标；核查旧CLI不能绕过新账户政策。
4. 独立审计：未来数据、schema越权、金额/仓位/换手/亏损、并发/重试、部分成交/撤单/T+1、来源及模型凭证隔离。
5. 主代理逐项review，亲自复算典型及极端账本，运行全套测试和CLI/合成端到端；修复后要求独立复核。
6. 更新三语文档与本轮验收报告，明确真实模型API、真实前向交易及OS部署条件中实际未验证的部分。

所有实验使用独立新路径或测试临时目录。模型服务付费额度、休市、数据源故障等外部条件如未满足，保留证据，不制造成功成交或收益。

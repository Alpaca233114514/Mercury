# A 股网络链路修复（2026-09-27）

## 已修复

旧隔离环境遗漏 `NO_PROXY` 等路由变量，导致正常宿主与 MCP 子进程的代理选择不一致。只读诊断显示正常权限宿主有 `NO_PROXY`，Windows 注册表另配本地代理；旧启动器丢失该偏好。现在所有子进程边界原样继承四个标准路由变量（HTTP_PROXY、HTTPS_PROXY、ALL_PROXY、NO_PROXY），保留大小写和值，不读出实际凭证或修改系统配置。受限环境的代理限制也不剔除。网络执行仍通过正式权限申请；TLS 校验、Auto Review、分支保护保持有效。

独立审计用合成认证代理 URL 复现上游错误回显可能泄漏凭证，因此增加启动前检查：包含 userinfo 或无法解析的代理地址固定脱敏拒绝，不静默移除代理或切换路由。CLI 桥、SDK helper、原生 stdio 入口及私有启动器均有检查。全套59项测试通过，含路由保留、API key 隔离、认证代理无回显/无子进程启动检查。详见[独立审计](ashare-audit-review.md)。

旧私有启动器及配置备份保留；当前为 `launch_stdio_network_v3.py`，通过新的启动器 SHA-256 验证。上游固定提交及源码清单没有改动。实现只改变环境继承与凭证拒绝，不修改供应商行情内容或历史账本。

## 实际网络结果

正常宿主的一个有界 HTTP 诊断请求曾返回200和48条分钟记录。这只是直接 HTTP 诊断，不能当作 MCP 链路成功，也没有导入交易数据库。

采集子代理随后通过修复后的 Mercury MCP 桥各调用一次分钟线、证券信息和实时报价；全部返回 `ok:false / data_source_unavailable`，此时错误是 `RemoteDisconnected` 而非旧的 `ProxyError`。分钟窗口为真实交易日2026-09-24 10:00–10:15，5分钟、未复权；失败与中秋休市无关。本地历史/统计/快照正常化均拒绝，没有写入行情或成交。

新私有证据：`data/integrations/ashare-route-v2-20260927T034130Z-e6d1bd9b/`，包含三类完整MCP响应、调用参数、采集时间及哈希。该轮使用无凭证路由；之后v3追加认证代理拒绝，不改变该路径。

有界参数对照及再次重复最初成功的同一HTTP请求也出现断连，因此目前不能把故障归因于某个参数，更不能宣称已找到稳定接口。各次诊断保留在 `data/integrations/ashare-parameter-*` 和 `ashare-control-20260927T034534Z.json`，没有用它们替代 MCP 证据或反复无限重试。
